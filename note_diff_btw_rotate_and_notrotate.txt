2.The pipeline to tilt odom will be completely seperate from the running vio
for the VIO node, run everything normally  map, odom, camera_link

we need to create child of these things. 
ground is child of map:               ros2 run tf2_ros static_transform_publisher 0 0 0 0 0.7854 0 camera_link drone_link
odom_tilt is child of odom:           ros2 run tf2_ros static_transform_publisher 0 0 0 0 -0.7854 0 map ground
drone_link is child of camera_link:   ros2 run tf2_ros static_transform_publisher 0 0 0 0 -0.7854 0 odom odom_tilt

use the same angle for all three things, just +,- sign for correction. The 6  numbers just make ros2 understand (translation + rotation)
The tf tree gives more context about this. Take a look. I attached it






3.The TF tree is now solve, we should see in RVIZ in accordance of what we want to see. Set fix frame to "ground", and we should see the odom, ground pararell to the grid, drone link pararell the grid 
at start, and camera_link tilt down at specify angle.

However, we need to pass odometry to px4, what I did is subscribing to odometry output from vio that using camera as a reference frame, and I rotate it at specify degree and then publish it to 
/mavros/odometry/out.

The package is vio_utils in this workspace
